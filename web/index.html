    Walk test

    Open this on your phone and walk the property. Every sensor that sees you shows here, with how strong its signal is and how long the hub took to hear it, and each node's light blinks green, yellow or red for its signal. Sensors still waiting at the end may not cover where you walked. The walk test lasts 10 minutes; alerts still reach the NVR meanwhile.

    Floor plan

      Pairing

      A node that supports pairing finds the hub by itself and gets a key of its own, so it never needs the ESP-NOW key above. Allow pairing, start the node in pairing mode, check that the fingerprint shown here matches the one on the node's label, and approve it. Its sensors are added for you.

      Sensor nodes

      Node firmware

      Put a node's new firmware.bin here, from the node project, one for each kind of chip. Each node of that chip running another version fetches it by itself after its next report, unless it is saving its battery; one whose update fails goes back to what it had, and does not try that file again. A node watches nothing while it updates, for a minute or so, and stops to report if its sensor fires.

      Notifications

      The hub can send each alert to a server on your network: an ntfy or Gotify server, which passes it on to your phone, a Home Assistant webhook, or Node-RED. Use http:// and an IP address; https and names are not supported, so services on the internet need a server on your network in between.

      Once a day, at this local time, one message: how many nodes were heard, any problems, the day's alerts and whether they reached the NVR, and when you last sent a test alert. If it stops arriving, the hub is off or cannot reach this address. Leave it empty for none; it needs the hub's clock.

      Once a week: the week's alerts and whether they reached the NVR, the sensor that fired most, the problems reported, batteries forecast to run out within a month, and the last test alert.

      Home Assistant

      The hub and each sensor appear in Home Assistant by themselves, through an MQTT broker: in Home Assistant, install the Mosquitto broker add-on and the MQTT integration, then enter the broker here. Home Assistant shows the hub as unavailable as soon as it loses its connection, so an automation can warn when the hub is unplugged or kept off the network.

      Leave the address empty to turn MQTT off. A password left blank keeps the saved one. The connection is not encrypted, as with the hub's other connections.

      Firmware update

      Choose the .bin for this board from a release, the one without -full. The hub takes only firmware signed for it, and keeps what it has if the file is anything else.

      Backup and restore

      The backup file holds the WiFi and hub passwords in plain text, so keep it somewhere safe. Pictures are not included.

      Download backup

      Full backup

      The settings, every picture, and each sensor's name and alert settings, in one file made by this browser. Restoring adds the sensors and pictures in it, replacing any with the same name, then replaces the settings and restarts the hub.

      New keys

      Makes a new ESP-NOW key, pairing key, sensor token and snapshot address, then restarts. Every sensor node must then be set up or paired again, HTTP sensors need the new token, and ONVIF clients the new snapshot address. Use it if a key may have got out.

      Reset settings

      Erases the saved WiFi networks, ports, name, web password, fixed address, time, notification and MQTT settings, and arms the hub. Pictures, sensor nodes, and the ESP-NOW key and token that sensors use, are kept.

      Time

      The NVR always receives UTC, so these settings only change the time shown here and the scheduled restart. After a power cut, a manual time is read once from the NTP server if the hub can reach it; otherwise set it again.
